1 — How the Update Process Works

1.1 Data Flow Overview

Data moves through five stages from NOVA to the final spreadsheet. Each stage produces an artifact that feeds the next.

1

Prerequisites & Authentication

Verify NOVA access is working, detect the browser automation tool, test SSO authentication, and confirm which funding rounds need updating.

Technical details
  1. Detect whether Claude-in-Chrome or Playwright MCP is available for browser automation
  2. Confirm SSO authentication by navigating to a known grant page and extracting the Plan ID via JavaScript — if empty after 5 seconds, SSO isn't active
  3. Ensure scraped_data.json exists (preserves previous round data during partial updates)
  4. Identify active rounds with final report deadlines not yet passed
  5. Confirm with the operator which rounds to update before proceeding
2

Dashboard Scan — Get Grant Listing

The NOVA Fiscal Reporting Dashboard is the authoritative source for the list of grants per round. The process reads the full dashboard, filters to Central Mother Lode institutions, and records the grant count, plan IDs, and approval statuses.

Technical details
  1. Navigate to nova.cccco.edu/swpk/fiscal-reports/plans
  2. Extract the full page text (all regions, all rounds)
  3. Filter to Central/Mother Lode grants by matching Lead Agency against the 68-institution list
  4. Filter by fiscal year to isolate the target round
  5. Record for each grant: Plan ID, Grant Name, Lead Institution, Submitted count (X/Y), Approval Status
  6. The total grant count per round becomes the expected row count used during validation
  7. Compare against the known plan IDs in scrape_round.py — flag any new or removed grants
3

Individual Grant Scraping

Each grant's fiscal report page is visited to extract financial data (budget, expenditures), then up to 2 additional FY pages are visited to determine which quarterly reports have been submitted. At ~6 seconds per page, a full round of 38 grants takes roughly 30–60 minutes.

Technical details

Per-grant scraping sequence:

  1. Navigate to nova.cccco.edu/swpk/fiscal-reports/plans/{planId}?duration={yearCode}
  2. Wait 5 seconds (SSO may redirect before auto-authenticating)
  3. Extract via JavaScript: Plan ID, Grant Name, Approval Status, financial totals (PTD Expenditure, Project Budget, Budget Remaining)
  4. Multi-institution grants produce multiple "Totals" rows — all are summed together
  5. Extract Q4 status from the primary page (this is the first FY page)
  6. Navigate to the 2nd FY page to get Q2 and Q4 status for that year
  7. Navigate to the 3rd FY page for Q2, Q4, and Final Report status
  8. Future FY pages (where no quarterly deadline has passed) are skipped — set to FALSE without navigating

Quarterly status values: Each FY page shows "Q2" or "Q4" on one line, followed by "Complete" or "Incomplete" on the next line. "Complete" = submitted (TRUE), "Incomplete" = not submitted (blank in spreadsheet).

Error handling: If Plan ID extracts as empty, the page hasn't loaded — retry once after 3 seconds. Grants that fail twice are logged to failed_grants.txt for manual review.

4

Spreadsheet Update

A Python script (regenerate_spreadsheet.py) rebuilds the Round 5–8 tabs from the scraped JSON data. Before modifying anything, it creates a timestamped backup. It preserves the Notes and Unexpended columns by matching on Proposal ID. R5 uses a 17-column layout (A–Q); R6–R8 use a 19-column layout (A–S) with Plan Status (L) and Lead LEA (M).

Technical details

Rebuild strategy per tab:

  1. Read existing data keyed by Proposal ID (column B)
  2. Find Notes and Unexpended columns by header text (not fixed index, since column positions differ per layout)
  3. Delete the old sheet
  4. Recreate with fresh scraped data: header row (blue fill, white text, Arial), data rows sorted alphabetically by Lead Institution, total row with SUM and COUNTIF formulas
  5. Restore preserved Notes and Unexpended values by matching Proposal ID

Run with: python3 regenerate_spreadsheet.py

5

Validation

An automated validation script (validate.py) automates 10 of the 18 checklist items on the scraped data and regenerated spreadsheet. The remaining 8 are manual checks. Automated checks include budget sanity, row counts, header matching, quarterly monotonicity, stale data detection, and cross-round deduplication.

Technical details

Automated checks (run via python3 validate.py):

3Budget sanity — all project budgets > $0 4Expenditure bounds — expenditures between $0 and budget (flags but doesn't reject over-budget) 5Budget remaining — budgetRemaining ≈ projectBudget - ptdExpenditure (within $1) 6Row count — data rows per tab match expected grant count 7Column headers — headers match expected layout for each round 8Sum validation — prints total budget and expenditure per round for review 13Quarterly monotonicity — if a later FY has TRUE, earlier FYs should also be TRUE 15Final report consistency — if all quarters TRUE and deadline passed, Final Report should be TRUE 16Cross-round dedup — no Plan ID appears in multiple rounds 18Stale data — flags past-due quarters still marked FALSE

Manual checks: Spot-check 3 random grant pages against scraped values, verify % Spent formulas, confirm Notes/Unexpended columns survived the rebuild.

2.4 Known Approximations & Edge Cases

  • Expenditures Approved is approximate. The scraper cannot distinguish approved vs. unapproved expenditure line items. If the overall grant status is "Approved" or "Certified," Approved equals Total Expenditures. If "Pending Approval," Approved is 0. This may slightly differ from granular per-line approval data. (Col N in R5, Col P in R6–R8.)
  • Q2 and Q4 are independent within a FY. A grant can have Q2 = Complete but Q4 = Incomplete on the same FY page. The primary page's approval status (Certified, Submitted, etc.) is not a reliable proxy for individual quarter status.
  • Multi-institution grants sum financial data. Grants with multiple reporting institutions produce multiple "Totals" rows in the Expenditure Report table. All rows are summed for the Grant Amount, Total Expenditures, and budget remaining columns. The institution count (Col C) comes from the dashboard, not from counting scraped rows.
  • Notes and Unexpended are never overwritten. These columns (P/Q in R5, R/S in R6–R8) are preserved across tab rebuilds by matching on Proposal ID. The script finds them by header text, not fixed column index. If a grant is removed from NOVA (no longer appears in the dashboard), its preserved values are logged as a warning but not carried forward.
  • $0 expenditure is normal for new grants. Early-lifecycle grants (especially R8) may have zero expenditures. The validation script flags these as warnings, not errors.
  • SSO redirects are expected. Every NOVA navigation may briefly redirect to a login page before auto-authenticating. The process waits 5 seconds after each navigation to allow this to complete.
